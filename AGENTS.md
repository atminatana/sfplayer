# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, Cursor and others) when working with code in this repository.

## Что это

`sfplayer` — SoundFont-синтезатор на Rust в собственном окне с сеткой символов (Windows / Linux): MIDI-вход → рендер через банк .sf2 → аудиовыход, с экраном «источники MIDI → обработчик → выход → запись» на библиотеке `gterm` (ADR 0012), игрой с текстовой клавиатуры и мышью на экранном пианино, проигрыванием MIDI-файла, встроенным синтезатором и записью в FLAC / Ogg Vorbis или в MIDI-файл.

**Состояние репозитория:** план v1.0 (`docs/plans/2026-10-20-sf2-player-v1.md`) выполнен по шагам 1.1–6.4; отчёты — `docs/done/`, `docs/test/`, `docs/verify/`; архитектурные решения — `docs/adr/`; текущее состояние модулей — `PROJECT_MAP.md`. Открытые пункты — живые проверки на оборудовании (MIDI-клавиатура, замер задержки, Linux) и первый прогон CI. Источник истины по требованиям и архитектуре — `docs/spec/2026-10-20-sf2-player-v1.md` (русский); редизайн главного экрана v1.1 (`docs/spec/2026-10-21-ui-redesign.md`) меняет §6, F-06 и F-20 и выводит монитор MIDI (F-08) и полосы каналов из экрана — при конфликте главнее v1.1; **v1.2 — оконный интерфейс на gterm, MIDI-файл, встроенный Synth, запись MIDI** (`docs/spec/2026-11-13-gterm-ui.md`, план `docs/plans/2026-11-13-gterm-ui.md` — выполнен, кроме шага 1.5: оконная подсистема Windows, лог только по ключу и CI на двух ОС ждут участия владельца; отчёты — `docs/done/`, `docs/test/`, `docs/verify/` с тем же именем файла) заменяет §6 v1.0 и §2–§4 v1.1 и при конфликте главнее обоих; **v1.3 — все управляющие элементы на контролах `gterm-widgets`, подтверждение отмены записи, сокращённая раскладка клавиш, лицензии, деление крупных файлов** (`docs/spec/2026-11-16-dialogs-and-keys.md`, план `docs/plans/2026-11-16-dialogs-and-keys.md` — выполнен; отчёты — `docs/done/`, `docs/test/`, `docs/verify/` с тем же именем файла) меняет окна и клавиши v1.0–v1.2 (таблица изменений — §3 ТЗ v1.3) и при конфликте главнее всех предыдущих; **v1.4 — драйверы аудиовыхода WASAPI, WASAPI Exclusive и ASIO в одном списке устройств, цепочка отката при отказе открытия** (`docs/spec/2026-11-23-audio-drivers.md`, план `docs/plans/2026-11-23-audio-drivers.md` — выполнен; отчёты — `docs/done/`, `docs/test/`, `docs/verify/` с тем же именем файла; открыто решение о дизеринге, ОР-4) меняет F-03, F-04 и строку «Выход», отменяет ADR 0003 и при конфликте главнее предыдущих. Перед реализацией любого модуля читать соответствующий раздел ТЗ: §4 архитектура, §5 функциональные требования (F-xx с приоритетами M/S/C), §6 UI и горячие клавиши, §7 нефункциональные (N-xx), §8 план из шести этапов.

Тестовый ассет: `assets/sin_wave.sf2` (1,2 КБ, синусоидальный банк) — для оффлайн-тестов синтеза, не для реальных банков. Реальные банки SF2 в репозиторий не кладутся (N-12).

Порядок работы над шагом (принят владельцем): `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` зелёные → разделы в `docs/done/` и `docs/test/` → обновление `PROJECT_MAP.md` → один коммит на шаг. Тесты крупных модулей лежат в подмодулях `*/tests.rs`; таблицы клавиш в README генерируются тестом `readme_keys` (`cargo test --test readme_keys print_table -- --nocapture`).

**README (обязательно на каждом шаге).** В корне два файла по конвенции GitHub: `README.md` — английский, `README.ru.md` — русский; в начале каждого — ссылки на оба языка. При любом изменении, видимом пользователю (CLI-флаги, горячие клавиши, поля конфига, форматы записи, индикаторы, зависимости сборки, ограничения), в том же шаге проверить и обновить **оба** README синхронно — содержание должно совпадать, расхождения между языками недопустимы. Таблицы клавиш не редактируются вручную: после изменения `src/ui/keys.rs` или словаря `locales/app.yml` перегенерировать их тестом `print_table` и вставить между маркерами `<!-- keys:start -->` / `<!-- keys:end -->`; тест `readme_keys` падает, если таблица устарела. Оба README попадают в релизные архивы (`.github/workflows/release.yml`).

## Команды

Тулчейн: stable (на старте 1.98), edition 2024, файла `rust-toolchain` нет.

```bash
cargo build --release            # релизная сборка; без ручной установки SDK (N-09)
cargo run -- --list-devices      # печать MIDI/аудио-устройств без запуска TUI
cargo run -- --sf2 assets/sin_wave.sf2
cargo test                       # все тесты
cargo test <имя_теста>           # один тест (подстрока имени)
cargo test --test <файл>         # один интеграционный тест из tests/
cargo clippy -- -D warnings      # обязателен зелёным (N-09, критерий приёмки)
cargo fmt
```

На Linux для cpal нужен `libasound2-dev`, для окна gterm — X11 или Wayland и fontconfig; для Ogg Vorbis (`vorbis_rs`) — компилятор C (MSVC / gcc).

## Архитектура (по ТЗ §4)

Пять потоков, аудио-поток никогда не ждёт остальных:

- **MIDI-поток** — callback `midir`, парсит байты в `MidiEvent`, кладёт в SPSC-кольцо.
- **Поток MIDI-файла** — секвенсор `midi/player.rs`: отдаёт события файла по времени в собственное SPSC-кольцо (ADR 0014); пока играть нечего, спит на канале команд.
- **Аудио-поток** — callback `cpal`, читает события/команды из трёх колец (файл, команды интерфейса, MIDI-вход), рендерит через `SynthEngine`, отдаёт измерения (пик/RMS, голоса, CPU, xrun, карты звучащих нот по источникам) через атомики, а для записи — сэмплы или, при формате MIDI, события с меткой кадра в свои кольца (ADR 0015).
- **Поток записи** — `record/`: живёт, пока идёт запись; разбирает кольцо записи и пишет FLAC, Ogg Vorbis или Standard MIDI File; кольца возвращаются сессии при любом исходе.
- **UI-поток** — главный поток процесса с циклом событий `gterm`; периодическая работа идёт от тика 33 мс, читает атомики, окно перерисовывается только при изменении экрана. Текстовая клавиатура (F-16) генерирует события в **тот же путь**, что и MIDI (кольцо команд → синтез).

Модули: `main.rs` (clap, конфиг, запуск потоков, окно), `session.rs` (состояние программы без окна: потоки, кольца, применение запросов интерфейса), `midi/` (разбор сообщений, порты, чтение и запись SMF, секвенсор), `record/`, `audio/` (устройства, поток, микшер, измеритель), `synth/` (трейт `SynthEngine`; два движка — `RustySynthEngine` для банка SoundFont и встроенный `BuiltinSynth` с ревербом и хорусом из `synth/effects/`, выбор — `synth.engine` в конфиге, ADR 0013), `ui/`, `config.rs` (TOML через `directories`).

Движок синтеза изолирован за трейтом — его сигнатура зафиксирована в ТЗ §3:

```rust
pub trait SynthEngine: Send {
    fn note_on(&mut self, ch: u8, key: u8, vel: u8);
    fn note_off(&mut self, ch: u8, key: u8);
    fn control_change(&mut self, ch: u8, cc: u8, value: u8);
    fn program_change(&mut self, ch: u8, program: u8);
    fn pitch_bend(&mut self, ch: u8, value: u16);
    fn render(&mut self, left: &mut [f32], right: &mut [f32]);
}
```

Стек (версии из ТЗ §2/§7 и v1.2): `midir 0.11`, `cpal 0.18`, `gterm` + `gterm-widgets` (git, фиксированный `rev`) и `winit 0.30` вместо `ratatui`/`crossterm`, `rustysynth 1.3` (основной), `oxisynth` (запасной), `ringbuf`, `clap 4`, `serde`+`toml`, `directories`, `tracing`+`tracing-appender`, `anyhow`/`thiserror`, `rust-i18n`, `flacenc`, `vorbis_rs`; на Windows — `windows 0.62` (монопольный режим WASAPI).

## Жёсткие ограничения из ТЗ

- **Аудио-коллбэк:** без аллокаций, блокировок и системных вызовов; обмен только через lock-free структуры и атомики (N-03). Кодирование записи — в отдельном потоке.
- **Горячие клавиши:** буквенных команд нет — буквы нижних рядов заняты текстовой клавиатурой. Все команды — на F-клавишах, Ctrl/Alt-сочетаниях и небуквенных клавишах. Раскладка ТЗ §6 с умолчаниями ТЗ v1.3 (F-28) — обязательна; справка F1 должна совпадать с реальной раскладкой.
- **Лицензии:** MIT/Apache и разрешительные BSL-1.0, ISC, BSD-2/3-Clause, Zlib (уточнение владельца, ADR 0012), Unicode-3.0 и MPL-2.0 — только у зависимостей без правок (решение владельца 16.11.2026, ADR 0016); LGPL запрещён (исключает `fluidlite`).
- **Аудио на Windows (ADR 0019):** драйвер выбирается вместе с устройством, имя выхода везде — `[Драйвер]: Имя устройства`. `WASAPI` — общий режим через cpal; `WASAPI Exclusive` — собственный поток в `audio/exclusive.rs`: единственный файл с `unsafe` и вызовами COM, компилируется только на Windows. `ASIO` — через cpal, только в сборке с возможностью `asio` (выключена по умолчанию; нужны LLVM, MSVC и SDK Steinberg; релизы собираются без неё): `cargo clippy --all-targets --features asio -- -D warnings && cargo test --features asio` с `LIBCLANG_PATH` и `CLANG_PATH` на LLVM. Аудио-коллбэк cpal получает блок в формате сэмплов устройства: `BlockRenderer::fill` обобщён по типу сэмпла, рендер остаётся f32.
- **Окно:** пока оно открыто, ничего в stdout — логи через `tracing` в файл; паника пишется в лог; при любом закрытии окна запись останавливается и конфиг сохраняется (`ui/window.rs`, `Drop`). Сам интерфейс не зависит от gterm нигде, кроме `ui/window.rs`, рисовальщиков, контролов главного экрана (`ui/controls.rs`) и окон на контролах (`ui/*_dialog.rs`); `App` от gterm не зависит.
- **Управляющие элементы (ADR 0018):** кнопки, списки, поля, флажки, ползунки и модальные окна — только контролы `gterm-widgets`; своих рисованных окон и своей обработки мыши и фокуса не заводить. Окно — модуль `ui/*_dialog.rs` со своими состояниями контролов; его экземпляр держит окно программы (`ui/window.rs`, `ui/window/layers.rs`), `App` только просит окно запросом. Нужного контрола нет — он добавляется в gterm, а не рисуется здесь.
- **UI:** все строки интерфейса — в словарях ru/en (`rust-i18n`), никаких захардкоженных текстов; перерисовка ≤ 30 кадров/с и только при изменении экрана; минимальная сетка 96×36 (правка fix1: рамка вокруг экрана, пианино в три строки, пустые строки у линий разделов).
- **Тесты (N-10):** отсутствие аллокаций в аудио-коллбэке — считающим аллокатором (`tests/no_alloc.rs`); unit — парсинг MIDI и микшер; интеграционный оффлайн-рендер (загрузить sf2, note_on, RMS > 0); UI-снимки — текст и цвета `gterm::buffer::ScreenBuffer` без открытия окна; контролы — через точки входа `Ui::route_key` / `route_mouse` / `modal_buffer`.
