# ТЗ: sf2\_player

Oct 20, 2026 · @Arsen Bulanov

## 1. Назначение

sf2\_player — консольный кроссплатформенный синтезатор на Rust: принимает ноты с MIDI-клавиатуры и в реальном времени проигрывает их через выбранный аудиовыход, используя банк SoundFont (.sf2). Приложение запускается в терминале (Windows, Linux, macOS), управляется горячими клавишами и показывает входящие MIDI-события, уровень выходного сигнала и главный микшер.

Базовый сценарий: пользователь запускает `sf2_player`, выбирает MIDI-вход, аудиоустройство и файл .sf2, нажимает клавишу на клавиатуре и слышит звук с задержкой не более 10–20 мс. Внутри программы он может менять громкость, пресет, канал и наблюдать поток MIDI-сообщений. Без MIDI-устройства ноты играются с двух нижних рядов текстовой клавиатуры; игру можно записать в сжатый аудиофайл. Интерфейс — на русском или английском по настройке.

Вне области ТЗ (версия 1.0): воспроизведение и запись MIDI-файлов, графический интерфейс, VST/плагины, сетевой MIDI, редактирование SoundFont.

Выводы по слоям:

1. MIDI: `midir` — единственный зрелый вариант; поддерживает hot-plug через повторное перечисление портов, но не уведомляет о подключении устройств (нужен опрос по таймеру).
2. Аудио: `cpal` даёт выбор устройства и фиксированный буфер; ASIO не используется (решение заказчика); на Windows — WASAPI в shared-режиме.
3. TUI: `ratatui` + `crossterm` — стандартная связка; событийный цикл с таймаутом 16–33 мс для перерисовки индикаторов.
4. Синтез: два живых pure-Rust кандидата — `rustysynth` (стабильный API 1.x, без зависимостей) и `oxisynth` (ближе к FluidSynth, SF3, эффекты вынесены в отдельные крейты). Оба рендерят в f32-буферы и вызываются из аудио-коллбэка без аллокаций.

Готовых консольных SoundFont-синтезаторов на Rust с TUI не найдено; ближайшие аналоги — `fluidsynth` (CLI, C) и GUI-приложение Neothesia.

## 3. Выбор: SoundFont или собственный синтез

Решение: поддержка формата SoundFont 2 через готовый pure-Rust синтезатор, основной кандидат — `rustysynth`, запасной — `oxisynth`. Собственный синтез (субтрактивный/FM) откладывается в бэклог как необязательный второй движок за общим трейтом `Synth`.

| Критерий | SoundFont (rustysynth / oxisynth) | Собственный синтез |
| --- | --- | --- |
| Качество звука «из коробки» | Реалистичные инструменты GM, 128 программ + ударные, бесплатные банки (GeneralUser GS, FluidR3, TimGM6mb) | Только синтетические тембры; качество зависит от объёма DSP-работы |
| Трудоёмкость до первого звука | 1–2 дня: загрузка .sf2, note\_on/off, render в cpal | 1–2 недели на осциллятор, огибающую ADSR, фильтр, полифонию, голосование |
| Соответствие требованию «выбор банка SoundFont» | Прямое | Невозможно без SF2-парсера |
| Контроль над алгоритмом | Ограничен API крейта (gain, reverb, chorus, program) | Полный |
| Зависимости и сборка | rustysynth: 0 зависимостей, MIT | 0 зависимостей |
| Риск | Баги в сторонней библиотеке; оба проекта активны (релизы 2026) | Риск недооценки сроков; тестирование DSP |

Аргументы за `rustysynth` как основного движка: стабильный API 1.x с 2023 года, последний релиз 01.10.2026, ноль зависимостей, встроенные реверб и хорус, метод `render` под стерео-буферы f32 без аллокаций. `oxisynth` оставить как альтернативу: он нужен, если потребуется SF3 (сжатые банки) или per-channel tuning; переключение возможно через feature-флаг `synth-oxi`.

Чтобы сохранить возможность собственного синтеза в будущем, движок изолируется за трейтом:

```rust
pub trait SynthEngine: Send {
    fn note_on(&mut self, ch: u8, key: u8, vel: u8);
    fn note_off(&mut self, ch: u8, key: u8);
    fn control_change(&mut self, ch: u8, cc: u8, value: u8);
    fn program_change(&mut self, ch: u8, program: u8);
    fn pitch_bend(&mut self, ch: u8, value: u16);
    fn render(&mut self, left: &mut [f32], right: &mut [f32]);
}
```

## 4. Архитектура

&#91;embedded content: архитектура sf2\_player · 3 потока, 4 очереди\]

Три потока: MIDI-поток принимает сообщения от midir, UI-поток ведёт ratatui, аудио-поток рендерит звук в коллбэке cpal. Аудио-поток никогда не ждёт других: события и команды приходят через SPSC-кольца (`ringbuf`), измерения уходят через атомики; UI читает очередь монитора и атомики по таймеру.

Модули крейта:

- `main.rs` — разбор CLI (clap), загрузка конфига, запуск потоков, восстановление терминала.
- `midi/` — перечисление портов, подключение, парсинг байтов в `MidiEvent`, опрос hot-plug.
- `audio/` — перечисление устройств cpal, открытие потока, коллбэк с `SynthEngine`, микшер, измеритель.
- `synth/` — трейт `SynthEngine`, реализация `RustySynthEngine` (feature `synth-oxi` — `OxiSynthEngine`), загрузка .sf2 и список пресетов.
- `ui/` — состояние приложения, виджеты панелей, модальные списки, раскладка клавиш.
- `config.rs` — структура TOML, пути по ОС, сохранение состояния.

## 6. Консольный UI и горячие клавиши

Один главный экран (минимум 80×24) с четырьмя панелями; настройки меняются в модальных диалогах поверх него. Фокус переключается Tab, активная панель выделена рамкой. Буквенных горячих клавиш нет: буквы двух нижних рядов заняты текстовой клавиатурой (F-16), поэтому все команды висят на F-клавишах, Ctrl/Alt-сочетаниях и небуквенных клавишах — пересечений между игрой и управлением нет.

Диалоги двух типов:

1. Селектор (MIDI-вход F2, аудиовыход F3, пресет F5, формат записи F6): модальное окно по центру с заголовком, списком вариантов и отметкой текущего; ↑↓/PgUp/PgDn — перемещение, набор текста — фильтр по списку, Enter — применить, Esc — отмена. Для аудиоустройств в строке под списком показываются частота и допустимый диапазон буфера; для формата записи — короткое описание (FLAC: без потерь, ≈3–5 МБ/мин; Ogg Vorbis: с потерями, ≈1 МБ/мин, качество из конфига).
2. Файл SF2 (F4): текстовое поле ввода пути с курсором, ←→/Home/End, Backspace/Delete, вставкой из буфера (Ctrl+V или вставка терминала), автодополнением имени файла и каталога по Tab и списком последних 10 банков под полем (↑↓ подставляет путь в поле). Enter — загрузить; при ошибке (нет файла, не SF2) сообщение показывается в диалоге, диалог не закрывается; Esc — отмена.

Текстовая клавиатура (F-16). Ноты играются всегда, когда не открыт диалог; отдельного режима и клавиши включения нет. Ctrl+буква приходит от терминала отдельным кодом и ноту не вызывает; не используются Ctrl+M, Ctrl+I, Ctrl+H и Ctrl+J, которые совпадают с Enter, Tab, Backspace и переводом строки. Раскладка повторяет пианино на двух нижних рядах, как в DAW:

```
  S  D     G  H  J     L  ;        ← чёрные клавиши (C#4 D#4 F#4 G#4 A#4 C#5 D#5)
 Z  X  C  V  B  N  M  ,  .  /     ← белые клавиши  (C4 D4 E4 F4 G4 A4 B4 C5 D5 E5)
```

| Клавиша | Действие |
| --- | --- |
| Z X C V B N M , . / | Белые клавиши C4–E5 (от базовой октавы); канал и пресет — текущие в микшере |
| S D G H J L ; | Чёрные клавиши C#4 D#4 F#4 G#4 A#4 C#5 D#5 |
| Ctrl+↓ / Ctrl+↑ | Октава −1 / +1 (диапазон C1–C7, базовая октава показывается в строке статуса) |
| Ctrl+← / Ctrl+→ | Velocity −10 / +10 (по умолчанию 100) |
| Esc | All Notes Off для нот с текстовой клавиатуры |

Раскладка (QWERTY или другая) переопределяется в конфиге, секция `[keyboard]`; там же — альтернативные сочетания для октавы и velocity на случай терминала, который не передаёт Ctrl+стрелки.

Снятие ноты: если терминал поддерживает расширенный протокол клавиатуры (kitty keyboard protocol — crossterm `PushKeyboardEnhancementFlags` с `REPORT_EVENT_TYPES`; поддерживают kitty, WezTerm, foot, Ghostty, Windows Terminal 1.19+), Note Off отправляется по реальному отпусканию клавиши. Иначе нота звучит фиксированное время `keyboard.gate_ms` (по умолчанию 300 мс) или до повторного нажатия той же клавиши; автоповтор клавиш подавляется. Режим определяется при старте и показывается в статусе как `kbd: release` или `kbd: gate 300ms`.

Требования к UI: перерисовка не чаще 30 кадров/с; UI-поток никогда не блокирует аудио; все строки монитора приходят из аудио/MIDI-потоков через lock-free очередь; раскладки клавиш переопределяются в конфиге (секция `[keys]`).

| N-01 | Платформы: Windows 10+ (x86\_64), Linux (x86\_64, glibc; ALSA/PipeWire), macOS 14+ (arm64, x86\_64). Один исходный код, сборка `cargo build --release` без ручной установки SDK |
| N-02 | Задержка «клавиша → звук» ≤ 15 мс при буфере 256 кадров/48 кГц на WASAPI/CoreAudio/ALSA hw; ≤ 30 мс при буфере по умолчанию |
| N-03 | Аудио-коллбэк без аллокаций, блокировок и системных вызовов; обмен с другими потоками только через lock-free структуры (`ringbuf`/`crossbeam` SPSC, атомики) |
| N-04 | Полифония ≥ 64 голоса при нагрузке аудиопотока ≤ 25 % на одном ядре ноутбука 2020 года |
| N-05 | Ноль xrun при 10 минутах непрерывной игры на буфере 256; счётчик xrun выводится в статусе |
| N-06 | Конфиг TOML в стандартном каталоге (`directories` crate: `%APPDATA%\sf2_player`, `~/.config/sf2_player`, `~/Library/Application Support/sf2_player`): устройства, банк, громкости, клавиши, каталог банков, язык интерфейса (ui.lang), каталог и формат записи (record.dir, record.format) |
| N-07 | Логирование через `tracing` в файл (уровень из `--log-level`), без вывода в stdout во время TUI; критичные ошибки — в строке статуса |

| N-10 | Тесты: unit-тесты парсинга MIDI и микшера; интеграционный тест «оффлайн-рендер» (загрузить sf2, note\_on, проверить ненулевой RMS); UI-снэпшоты через `TestBackend` ratatui |
| N-11 | Лицензия проекта MIT или Apache-2.0; все зависимости — MIT/Apache; без LGPL (исключает `fluidlite`) |

Основные зависимости (Cargo.toml): `midir 0.11`, `cpal 0.18`, `ratatui 0.30`, `crossterm 0.29`, `rustysynth 1.3`, `ringbuf`, `clap 4`, `serde` + `toml`, `directories`, `tracing` + `tracing-appender`, `anyhow`/`thiserror`.

Для F-19 и F-20 дополнительно: `rust-i18n` (словари ru/en в YAML, MIT), [flacenc 0.5](https://docs.rs/crate/flacenc/latest) (Apache-2.0, pure Rust) и [vorbis\_rs 0.5](https://docs.rs/crate/vorbis_rs/latest) (BSD-3, собирает libogg/libvorbis из исходников через cc). Оба энкодера входят в сборку по умолчанию, формат выбирает пользователь; кодирование идёт в отдельном потоке. Для Vorbis при сборке нужен компилятор C: MSVC на Windows, Xcode CLT на macOS, gcc/clang на Linux.

## 8. План реализации и критерии приёмки

Шесть этапов, каждый заканчивается работающим бинарником; оценка — для одного разработчика.

1. Каркас и звук без UI (2–3 дня). Cargo-проект, модули `audio`, `midi`, `synth`, `app`; cpal-поток с rustysynth; `--sf2` + `--list-devices`; нота по MIDI звучит. Приёмка: оффлайн-тест RMS > 0, звук на трёх ОС.
2. Устройства и конфиг (2 дня). Перечисление и выбор MIDI/аудио из CLI и конфига, fallback на устройство по умолчанию, обработка отключения. Приёмка: отключение клавиатуры не роняет программу, статус обновляется ≤ 2 с.
3. TUI-скелет (3 дня). ratatui + crossterm, главный экран, модальные списки (F-01, F-03, F-05, F-06), справка, восстановление терминала при панике. Приёмка: все списки открываются и закрываются, UI-снэпшоты проходят.
4. Монитор, индикаторы, микшер (3–4 дня). Lock-free очередь событий в UI, монитор MIDI (F-08), измеритель уровня (F-09), микшер (F-10), panic (F-11), счётчик голосов и CPU (F-12), текстовая клавиатура с определением протокола key-release (F-16). Приёмка: 30 кадров/с, UI не вызывает xrun при 10 мин игры.
5. Удобства (3–4 дня). Реверб/хорус, транспонирование, omni-канал, сохранение состояния (F-13–F-15), локализация RU/EN (F-19), запись в FLAC (F-20), переопределение клавиш.
6. Стабилизация и релиз (2–3 дня). CI на трёх ОС, замер задержки (N-02) через loopback-запись, README, бинарники в GitHub Releases.

Итого 15–19 рабочих дней до v1.0; собственный движок синтеза (F-17) — отдельно, не менее 10 дней.

Критерии приёмки v1.0:

- [ ] На Windows, Linux и macOS нота с MIDI-клавиатуры звучит через выбранный выход с задержкой ≤ 15 мс (буфер 256/48 кГц)
- [ ] Все требования с приоритетом M выполнены и проверены вручную по чек-листу
- [ ] 10 минут игры без xrun и без падений; отключение/подключение MIDI-устройства обрабатывается
- [ ] Клавиши из раздела 6 работают; справка F1 совпадает с реальной раскладкой; ноты с текстовой клавиатуры звучат и попадают в монитор MIDI
- [ ] `cargo test`, `cargo clippy -D warnings` и CI на трёх ОС зелёные

## 9. Риски и открытые вопросы

| Риск | Влияние | Снижение |
| --- | --- | --- |
| Задержка WASAPI в shared-режиме > 15 мс на некоторых драйверах | Не выполняется N-02 на Windows | Feature `asio` не используется (решение заказчика); документировать требование к буферу и драйверу; замерить на этапе 1, при необходимости задать больший буфер в конфиге |
| Сборка cpal на Linux требует `libasound2-dev`; PipeWire держит ALSA `default` | Ошибка DeviceBusy у части пользователей | Feature `pipewire`/`pulseaudio`, в README — список пакетов; fallback на устройство `pipewire`/`pulse` |
| midir не уведомляет о hot-plug | Пользователь не видит новую клавиатуру | Опрос списка портов раз в 2 с в фоновом потоке, клавиша `r` |
| Баги или пробелы в rustysynth (например, редкие генераторы SF2) | Неверный звук в отдельных банках | Трейт `SynthEngine` и feature `synth-oxi` для быстрой замены на oxisynth |
| Терминал без поддержки Unicode-блоков (cmd.exe, старые tty) | Индикаторы отображаются неверно | ASCII-режим индикаторов по флагу `--ascii` и автоопределение |
| Нажатия клавиш без key-release в терминале | Текстовая клавиатура (F-16) не получает отпускание клавиш в обычных терминалах | Kitty keyboard protocol где доступен (определяется при старте); иначе gate-режим с настраиваемой длительностью и note-off по повторному нажатию; в README — список терминалов с поддержкой release |

Вопросы заказчику и ответы (получены 20.10.2026):

- [x] ASIO в v1.0 не нужен — только WASAPI shared

- [x] Минимальный размер терминала 80×24 достаточен

- [x] Устройства, пресет и формат записи выбираются в диалогах-селекторах, файл SF2 — в диалоге с текстовым полем
