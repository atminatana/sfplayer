# 0012. ASIO как опциональный feature: единый список устройств, поток в формате драйвера

- **Дата:** 2026-10-22
- **Статус:** Accepted (решение владельца и ОР-1…ОР-3 ТЗ v1.2, приняты 22.10.2026); заменяет [0003](0003-windows-wasapi-shared.md) для сборок с feature `asio`
- **Тема:** аудиобэкенд на Windows; формат сэмплов выходного потока

## Контекст

ADR 0003 отказался от ASIO по двум причинам: SDK Steinberg с собственной лицензией и сборка, требующая LLVM и MSVC, что ломает «`cargo build` без ручной установки SDK» (N-09, N-11). Владелец пересмотрел решение: ASIO нужен тем, кому важна задержка, но не ценой обычной сборки и релизов. Дополнительно выяснилось, что ASIO-бэкенд cpal не конвертирует формат сэмплов: поток обязан быть в формате драйвера (обычно Int32), а наш рендер — f32.

## Решение

1. Cargo-feature `asio = ["cpal/asio"]`, выключен по умолчанию. Сборка без него не компилирует `asio-sys`; CI проверяет сборку с feature отдельным шагом на `windows-latest` с `continue-on-error`; релизные архивы собираются без ASIO.
2. Отдельного переключателя бэкенда нет. Одно перечисление `enumerate_outputs()`: устройства хоста по умолчанию в прежнем порядке, затем ASIO-драйверы с пометкой `[ASIO]` в имени. Выбор — как для любого устройства (`--audio-out`, `audio.output`, F3); без feature, при ошибке хоста ASIO или без драйверов ASIO-строк просто нет, ошибка хоста уходит в лог.
3. Поток открывается в формате `default_output_config().sample_format()` устройства: `BlockRenderer::fill` обобщён по `T: cpal::Sample + FromSample<f32>` и конвертирует каждый сэмпл при интерливе; измеритель, клип-детектор и запись по-прежнему читают f32-рендер. Для WASAPI (f32) поведение не меняется.

## Альтернативы и обоснование

- Поле `audio.backend` + `--audio-backend` с fallback на WASAPI — лишний переключатель и состояние «запрошен ASIO, но его нет»; владелец выбрал единый список: устройство само определяет бэкенд, а конфиг хранит имя с пометкой.
- ASIO всегда включён на Windows — нарушает N-09/N-11 для каждого, кто собирает проект.
- Конвертация формата через промежуточный буфер в `open_output_stream` — второй проход по данным и ещё один scratch; обобщение `fill` стоит одного вызова `from_sample` на сэмпл и для f32 бесплатно.
- Релизный архив с ASIO — бинарник, собранный с SDK Steinberg, требует отдельной проверки лицензии; отклонено владельцем.

## Последствия

- (+) Обычная сборка, CI на трёх ОС и релизы не меняются; индексы устройств из существующих конфигов сохраняются.
- (+) Любой cpal-хост с не-f32 форматом (включая будущие) обслуживается тем же кодом.
- (−) Пользователь ASIO собирает сам: LLVM, MSVC, загрузка SDK при первой сборке; `xrun` при ASIO всегда 0 (cpal не сообщает); драйвер монопольный.
- (−) `Cargo.lock` содержит `asio-sys` и его сборочные зависимости, хотя они не компилируются без feature.
