# 0009. События текстовой клавиатуры через кольцо команд UI→audio

- **Дата:** 2026-10-20
- **Статус:** Accepted (OD-4 плана, принято владельцем)
- **Тема:** путь нот с текстовой клавиатуры (F-16)

## Контекст

F-16 требует, чтобы ноты с текстовой клавиатуры шли «тем же путём, что и MIDI» — в монитор и синтез. Кольцо `midi_events` SPSC: его производитель — MIDI-поток, UI-поток писать в него не может (ADR 0002).

## Решение

UI-поток отправляет ноты как `Command::Midi(MidiEvent)` в своё кольцо `ui_commands`. Аудио-поток на каждом блоке сливает `midi_events` и `ui_commands` и передаёт оба потока событий в `SynthEngine` одним обработчиком (транспонирование, omni-канал, микшер применяются одинаково). В монитор UI добавляет запись сам, без кольца.

## Альтернативы и обоснование

- MPSC-очередь с двумя производителями — лишняя зависимость и более дорогие операции; у SPSC один производитель на кольцо, что здесь соблюдается.

## Последствия

- (+) Остаёмся на `ringbuf`, N-03 соблюдён; один обработчик событий в аудио-потоке.
- (−) Два источника событий — порядок между ними внутри одного блока не гарантирован (несущественно при блоке ≤ 5 мс).
