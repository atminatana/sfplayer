# 0017. Крупные файлы делятся на подмодули по ответственности

- **Дата:** 2026-11-16
- **Статус:** Accepted (решение владельца 16.11.2026 по отложенному вопросу из `TODO.md`; ТЗ v1.3 §6)
- **Тема:** схема деления `src/session.rs`, `src/ui/app.rs` и `src/ui/main_screen.rs`

## Контекст

После плана v1.2 три файла вышли за ориентир в 500 строк: `src/ui/main_screen.rs` — 721, `src/ui/app.rs` — 569, `src/session.rs` — 546. Ближайшие шаги v1.3 (окна на контролах, подтверждение отмены записи, выпадающие списки) правят именно их. В проекте уже есть образец: применение запросов интерфейса вынесено из `session.rs` в `session/control.rs`.

## Решение

Файл делится на подмодули по группам ответственности; тип остаётся один, его методы расходятся по файлам.

| Файл | Выносится | Остаётся |
| --- | --- | --- |
| `src/session.rs` | `session/devices.rs` — аудиопоток и MIDI-порт: открытие, смена, пересканирование, подключение; `session/recording.rs` — запись: старт, стоп, отмена, сведения о записи, папка | состав сессии, запуск, банк и движок, сохранение конфига, опрос |
| `src/ui/app.rs` | `ui/fulfil.rs` — применение запросов интерфейса к сессии | типы запросов и кнопок, автомат ввода `App` |
| `src/ui/main_screen.rs` | `main_screen/sources.rs` — источники и MIDI-файл; `main_screen/handler.rs` — обработчик, Synth, Sound Font; `main_screen/output.rs` — выход, измеритель, строка записи | раскладка экрана, `render`, общие помощники, строка состояния |

Правила переноса:

- Перенос механический: текст функций переезжает без правок, отдельным набором изменений, не смешанным с правками логики.
- Меняются только объявления модулей, импорты, заголовки файлов и видимость: помощник, который вызывается из другого файла того же модуля, получает `pub(super)`.
- До переноса проверяется, что переносимое покрыто тестами; чего не хватает и что достижимо без оборудования — дописывается отдельным набором изменений перед переносом.
- Тождество текста проверяется сверкой строк до и после; утверждения тестов не правятся — тесты остаются на месте либо переезжают вместе со своей функцией.

## Альтернативы и обоснование

- **Не делить, обосновать цельность** («один рисовальщик одного экрана», «одна сессия») — отклонено владельцем: файлы продолжили бы расти под ближайшими шагами.
- **Делить только файл, который меняют ближайшие шаги** — отклонено: вопрос остался бы открытым наполовину.
- **Выделить новые типы** (отдельный объект записи со своим состоянием, отдельный объект устройств) — отклонено: это изменение устройства сессии, а не перенос; его нельзя проверить сверкой текста, а тестов на пути с настоящими устройствами нет.

## Последствия

- (+) Три файла уходят ниже ориентира; новые правки приходят в файлы с одной ответственностью.
- (+) Перенос проверяем без тестов на оборудовании: компилятор и сверка строк.
- (−) Методы одного типа лежат в нескольких файлах: искать метод приходится по модулю, а не по типу.
- (−) Часть помощников стала видна всему модулю (`pub(super)`), а не одному файлу.
- (−) Страховочные тесты сессии покрывают только пути без устройств; открытие потока, смена устройства и запись при живом потоке по-прежнему проверяются вручную.
