# 0002. Потоковая модель: аудио-поток без блокировок, SPSC-кольца и атомики

- **Дата:** 2026-10-20
- **Статус:** Accepted
- **Тема:** межпоточное взаимодействие

## Контекст

Задержка «клавиша → звук» ≤ 15 мс при буфере 256/48 кГц и ноль xrun за 10 минут (N-02, N-05). Три основных потока: MIDI (callback midir), аудио (callback cpal), UI (ratatui) — ТЗ §4.

## Решение

Аудио-поток никогда не ждёт другие потоки. Весь обмен:

- MIDI → audio: SPSC-кольцо `midi_events` (`ringbuf`);
- UI → audio: SPSC-кольцо `ui_commands` (громкость, mute, пресет, panic, события текстовой клавиатуры — ADR 0009);
- MIDI → UI: SPSC-кольцо `monitor_midi` с записями фиксированного размера;
- audio → UI: атомики (peak/RMS L/R, голоса, CPU %, xrun);
- audio → поток записи: SPSC-кольцо `rec_samples`.

В коллбэке запрещены аллокации, `Mutex`, системные вызовы, логирование.

Служебные потоки (опрос hot-plug MIDI раз в 2 с, кодирование записи) с аудио-потоком не взаимодействуют напрямую.

## Альтернативы и обоснование

- `Mutex<State>` между UI и аудио — приоритетная инверсия и xrun; отклонён (N-03).
- MPSC (`crossbeam::ArrayQueue`) — допустимо, но SPSC проще и быстрее; у каждого кольца ровно один производитель, поэтому MPSC не нужен.
- Каналы `std::sync::mpsc` — аллоцируют при отправке; отклонены для пути в аудио.

## Последствия

- (+) Детерминированная задержка; измерения UI не влияют на звук.
- (−) Событие, не поместившееся в кольцо, теряется — размер колец выбирается с запасом (≥ 1024 событий), переполнение считается и показывается в логе.
