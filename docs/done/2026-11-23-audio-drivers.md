## Шаг 1.1 — драйвер и единый список (2026-11-23)

- `src/audio/device.rs`: `Driver` (`Host`, `WasapiExclusive`, `Asio`) с названием для списка; `output_label` — имя выхода `[Драйвер]: Имя устройства`; `OutputDevice` — устройство с драйвером; одно перечисление `enumerate_outputs` для списка, выбора по подстроке или индексу и выхода по индексу; `AudioDeviceInfo` получил `driver` и `label()`. На этом шаге перечисление отдаёт только выходы драйвера ОС; строки `WASAPI Exclusive` и `ASIO` добавляют шаги 2.2 и 3.1.
- `src/audio/stream.rs`: поток открывается на `OutputDevice`; `AudioStream.label` вместо `device_name` — полное имя выхода; оно же в логе и в текстах ошибок открытия.
- `src/session/devices.rs`, `src/ui/view.rs`: `audio.output`, сообщение о смене выхода и поле строки «Выход» несут полное имя.
- `src/ui/devices.rs`: строки выпадающего списка — полные имена.
- `src/main.rs`: `--list-devices` печатает полные имена.
- `docs/adr/0019-audio-output-drivers.md` (новый), индекс ADR; ADR 0003 — Superseded by 0019.
- `README.md`, `README.ru.md`: вид имени выхода в `--list-devices`, `--audio-out` и `audio.output`.

**COMPLETENESS** — план, шаг 1.1 / ТЗ D-01…D-05, D-07: имя выхода с драйвером во всех пяти местах (список, строка «Выход», лог, `--list-devices`, `audio.output`); порядок и нумерация — одно перечисление; поиск по полному имени; нечитаемое устройство по-прежнему пропускается с `warn`. Тесты — раздел шага в `docs/test/`. D-05 для драйверов, которых ещё нет в перечислении, закрывается на шагах 2.2 и 3.1.

**CORRECTNESS** — живой прогон `cargo run -- --list-devices` на машине владельца: `[0] [WASAPI]: Динамики (Realtek(R) Audio)`, `* [1] [WASAPI]: Наушники (2- QCY H3 Stereo)`, `[2] [WASAPI]: Головной телефон (QCY H3 Hands-Free AG Audio)` — индексы и отметка умолчания те же, что до правки. Значение `audio.output = "Наушники (2- QCY H3 Stereo)"` из действующего конфига находит тот же выход: поиск идёт подстрокой по полному имени (тест `a_device_name_from_an_old_config_finds_the_output_of_the_host_driver`).

**EVIDENCE** — `cargo fmt --check` ok; `cargo clippy --all-targets -- -D warnings` чисто; `cargo test`: 409 unit + 3 i18n + 4 no_alloc + 2 readme = 418 passed, 0 failed (базовый прогон до правок — 413).

**⚠ WARNINGS**

- **Поле строки «Выход» ещё 40 ячеек:** имя с драйвером длиннее и обрезается раньше; ширина и обрезка — шаг 1.2.
- **Открытое решение ОР-4** (дизеринг при переводе в 16 бит) — в плане; шаг 2.1 идёт по допущению Д-5.
- **Имя устройства без названия** в выборе по подстроке теперь `device N`, как в списке (раньше — пустая строка): для устройств с именем поведение не изменилось.

## Шаг 1.2 — строка «Выход» (2026-11-23)

- `src/ui/main_screen.rs`, `main_screen/output.rs`: поле аудиовыхода — 50 ячеек (`AUDIO_OUT_CELLS`; поле MIDI-входа осталось 40); после него — частота и число кадров одного коллбэка без слова «кадров» (`48000 Hz / 480`), а если драйвер размер не сообщает — одна частота; текст ошибки строки обрезается у отступа рамки.
- `src/audio/stream.rs`, `src/ui/view.rs`: `AudioStream.buffer_frames` — размер коллбэка, который сообщает поток (`StreamTrait::buffer_size`), вместо запрошенного; в логе старта потока — и запрошенный, и действующий.
- `src/ui/controls.rs`: текст поля и строки раскрытого списка длиннее поля обрезаются с `…`; значение по-прежнему ищется в списке по полному имени.
- `src/ui/paint.rs`: `fitted` перенесён сюда из `main_screen.rs` — им пользуются и экран, и контролы.
- `locales/app.yml`: ключи `header.buffer` и `header.buffer_default` удалены — текстов больше нет.
- `README.md`, `README.ru.md`: что показывает строка «Выход» после частоты.
- ТЗ D-06 уточнено: имя до 28 знаков вместо 30.

**COMPLETENESS** — план, шаг 1.2 / ТЗ D-06, Д-3: поле вмещает `[WASAPI Exclusive]: ` и имя до 28 знаков на сетке 96×36, длинное имя обрезается с `…` в поле и в списке, размер коллбэка — действующий. Тесты — раздел шага в `docs/test/`.

**CORRECTNESS** — оба устройства владельца («Динамики (Realtek(R) Audio)» и «Наушники (2- QCY H3 Stereo)», по 27 знаков) с драйвером `WASAPI Exclusive` входят в поле целиком, и за ним остаётся место для `48000 Hz / 256  OK` (тест `the_output_field_has_room_for_an_exclusive_output_and_what_follows_it`). Для потока cpal на WASAPI `buffer_size()` возвращает период устройства (`cpal-0.18.2/src/host/wasapi/stream.rs:523`) — те 480 кадров, что показал замер.

**EVIDENCE** — `cargo fmt --check` ok; `cargo clippy --all-targets -- -D warnings` чисто; `cargo test`: 414 unit + 3 i18n + 4 no_alloc + 2 readme = 423 passed, 0 failed. Один новый тест при первом прогоне упал из-за ошибки в ожидаемой строке (48 знаков вместо 47 + `…`); исправлено ожидание, код не менялся.

**⚠ WARNINGS**

- **Вживую в окне не проверено:** строка «Выход» и раскрытый список проверены снимками `ScreenBuffer`; число после частоты в настоящем окне (ожидается 480 для «Динамиков») — взгляд владельца.
- **Обрезка с `…` действует для всех трёх выпадающих списков**, не только для аудиовыхода: механизм общий. Для MIDI-входа и формата записи вид меняется только у имени длиннее поля (раньше оно обрывалось без знака).
- **`src/ui/controls.rs` — 498 строк** при пороге проекта 500: следующая правка этого файла потребует деления или обоснования.
- **Место для текста ошибки в строке «Выход» сократилось** с 30 до 20 ячеек из-за ширины поля; ошибка обрезается с `…`. Сообщения цепочки отката (шаг 2.3) пойдут в строку сообщений под «Записью».

## Шаг 2.1 — перевод f32 → PCM 16 и 24 бита (2026-11-23)

- `src/audio/pcm.rs` (новый): `PcmFormat` (`I24` — три байта, `I16`) с порядком опроса устройства `PREFERRED`; `write_pcm` — запись f32 в байты PCM с младшего байта, округлением до ближайшего шага, насыщением за пределами ±1 и тишиной вместо не-числа. Память не выделяется. К потоку функция подключается на шаге 2.2.
- `src/audio/mod.rs`: модуль `pcm`.

**COMPLETENESS** — план, шаг 2.1 / ТЗ E-01 (порядок форматов), К-3 (крайние значения, тишина, насыщение): код и тесты есть. E-04 (измеритель и запись читают f32 до перевода) выполняется устройством шага 2.2: перевод — последнее действие над блоком.

**CORRECTNESS** — `1.0` даёт наибольшее значение формата, `-1.0` — наименьшее; половина шага округляется по правилу `round`; 24-битный сэмпл проверен побайтно на известном числе `0x010203` и его отрицании.

**EVIDENCE** — `cargo fmt --check` ok; `cargo clippy --all-targets -- -D warnings` чисто (первый прогон дал два замечания `chunks_exact_to_as_chunks` в тестах — исправлено); `cargo test`: 420 unit + 3 i18n + 4 no_alloc + 2 readme = 429 passed, 0 failed.
