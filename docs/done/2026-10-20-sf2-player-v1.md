## Шаг 1.4 — audio/: устройства cpal, поток, коллбэк (2026-10-20)

**Сделано**

- `src/audio/shared.rs`: `AudioShared` — мастер-гейн (биты f32 в `AtomicU32`, clamp 0..1) и счётчик xrun; единственный канал audio → другие потоки, как требует ADR 0002.
- `src/audio/render.rs`: `BlockRenderer` — ядро коллбэка: вычитывает `MidiEvent` из SPSC-кольца, применяет к `SynthEngine`, рендерит чанками ≤ 4096 кадров в заранее выделенные буферы, применяет гейн и интерливит в выход (моно — среднее L/R, каналы > 2 — тишина). Без аллокаций и блокировок после `new`.
- `src/audio/device.rs`: `list_output_devices()` (индекс, имя, признак умолчания, частота, диапазон буфера), `default_output_device()`.
- `src/audio/stream.rs`: `open_output_stream` — stereo f32, частота из CLI или устройства, `BufferSize::Fixed(n)` с настоящим fallback на `Default` (F-04); движок и кольцо создаются внутри каждой попытки, потому что cpal забирает замыкания даже при неудаче; возвращает поток и производителя кольца (ёмкость 1024). Ошибки cpal с `ErrorKind::Xrun` считаются в `AudioShared`, остальные — в лог.
- `main.rs`: `--list-devices` печатает аудиовыходы и выходит; с `--sf2` открывает поток на устройстве по умолчанию и ждёт Enter (временный режим до TUI), по выходу печатает число xrun.

**COMPLETENESS** — F-03 перечисление: код + ручная проверка; F-04 поток и fallback: код, ручная проверка основного пути; ядро коллбэка: код + 7 тестов; `AudioShared`: 2 теста.

**CORRECTNESS** — тесты ядра: тишина без событий, нота из кольца звучит на L и R, гейн 0 даёт тишину, моно и 4-канальный выход, буфер длиннее чанка (8315 кадров) обрабатывается целиком, note off через кольцо гасит звук.

**EVIDENCE** — `cargo fmt --check` ok; `cargo clippy --all-targets -- -D warnings` чисто; `cargo test`: 42 passed, 0 failed (0.12 s). Живые проверки на Windows: `--list-devices` → «* [0] Динамики (Realtek(R) Audio) 48000 Hz, buffer 480..480 frames»; воспроизведение 2 с с буфером 256 и 1 с с буфером 64 → exit 0, xruns 0, лог `audio stream started … buffer_size=Fixed(256|64)`. LOC: render.rs 224, stream.rs 100, shared.rs 65, device.rs 51, main.rs 63.

**⚠ WARNINGS**

## Фикс — пропуск устройств с нечитаемой конфигурацией (2026-10-20)

**Повод** — жалоба: при попытке выбрать аудиоустройство (F3) и в `--list-devices` ошибка «Аудио: cannot read device configuration for HDA Intel PCH, ALC897 Analog» без указания причины, список недоступен целиком.

**Диагноз** — причина в src/audio/device.rs, не в оборудовании. cpal на ALSA читает конфигурацию устройства реальным открытием PCM, а ALSA-hint `surround21:CARD=PCH,DEV=0` для кодека ALC897 не может открыть 2-канальный аналоговый выход (route-плагин: «Found no matching channel map» → EINVAL → «Device does not support output»). `list_output_devices` прерывал **всё** перечисление при отказе первого же устройства. Имя в сообщении обманчиво: DESC hint-ов на этой системе начинается с имени карты, поэтому под именем «HDA Intel PCH, ALC897 Analog» скрыты `sysdefault`/`front`/`surround21`/`surround40…71` — отказался именно `surround21`. Текст ошибки терял `{source}` (thiserror не включает его в Display), и notice-путь не писал источник в лог — реальная причина была недиагностируема.

**Сделано**

- `src/audio/device.rs`: `list_output_devices` при отказе `default_output_config` у конкретного устройства пишет `tracing::warn!` с источником и пропускает его, продолжая цикл; фатальной остаётся только ошибка самого перечисления (`AudioError::Devices`). Индексы остаются позициями полного перечисления (`enumerate()` до пропуска), поэтому маппинг строк диалога → `output_device_by_index` (`.nth`) не изменился.
- `src/audio/mod.rs`: `AudioError::DeviceConfig` показывает причину — `cannot read device configuration for {device}: {source}`; в notice «Аудио: …» и в лог попадает, например, «Device does not support output».
- Тест `audio::tests::device_config_error_names_the_device_and_the_cause`: Display содержит и устройство, и причину (source собирается через публичный `cpal::Error::with_message`).
- README.md/README.ru.md: строка о пропуске непрочитаемых устройств с предупреждением в логе (синхронно на обоих языках).

**COMPLETENESS** — исправлены обе точки отказа перечисления: F3-диалог (`ui/app.rs: fulfil`) и `--list-devices` (`main.rs: print_devices`).

**CORRECTNESS** — живой прогон на машине с воспроизведённой ошибкой: `--list-devices` до фикса падал с exit 1 на первой же записи surround21; после фикса печатает полный список (exit 0), пропущено 3 surround-записи ALC897, занятый HDMI («temporarily busy») и USB FM-1 без поддержки форматов — каждая с предупреждением в логе; выбор рабочего устройства F3 не затронут.
