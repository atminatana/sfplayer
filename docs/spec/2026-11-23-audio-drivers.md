# ТЗ: драйверы аудиовыхода — WASAPI, WASAPI Exclusive, ASIO — в одном списке устройств (v1.4)

Nov 23, 2026 · черновик агента по постановке владельца от 23.11.2026; открытые решения ОР-1…ОР-3 (§8) **приняты владельцем 23.11.2026** — ТЗ действует с этими ответами; ОР-4 (дизеринг) не решён и перенесён в план как открытое решение, до ответа действует допущение Д-5. План — `docs/plans/2026-11-23-audio-drivers.md`. Базовые ТЗ — `docs/spec/2026-10-20-sf2-player-v1.md` (v1.0) … `docs/spec/2026-11-16-dialogs-and-keys.md` (v1.3); этот документ меняет F-03, F-04 и строку «Выход» (F-26.1 v1.3), отменяет ADR 0003 («только WASAPI shared») и при конфликте главнее предыдущих.

Постановка владельца: «Между нажатием на клавишу и началом звукоизвлечения заметная пауза… Задержку даёт аудиоподсистема винды. Сделай выпадающий список аудиоустройств в формате `[Драйвер]: Имя устройства`. Драйвера: WASAPI, WASAPI Exclusive и ASIO (если доступно)».

## 1. Цель

Дать на Windows путь к задержке «клавиша → звук» в пределах N-02 (≤ 15 мс): драйвер выбирается вместе с устройством в том же выпадающем списке строки «Выход». Обычный WASAPI остаётся умолчанием и работает как раньше.

## 3. Границы

**Входит**

- Понятие драйвера аудиовыхода и единый список «драйвер + устройство» (§4.1).
- Драйвер **WASAPI Exclusive** на Windows (§4.2).
- Драйвер **ASIO** на Windows в сборке с возможностью `asio` — перенос работы из `origin/develop` (§4.3; объём и порядок — ОР-1).
- Строка «Выход», `--list-devices`, `--audio-out`, `audio.output` (§4.1, §5).
- Документы: ADR взамен 0003, README ×2, `PROJECT_MAP.md`, `AGENTS.md`.

**Не входит**

- Автоматическое пересоздание потока после отключения устройства (сейчас только запись в лог) — отдельная задача.
- `IAudioClient3`, патч cpal для shared-режима, JACK, ASIO-вход, панель управления драйвера ASIO.
- Изменение поведения на Linux, кроме формата строки списка (Д-1).
- ASIO в релизных архивах (решение владельца от 22.10.2026, ОР-3 того ТЗ).

## 4. Требования

Приоритеты: M — обязательно, S — желательно.

### 4.1 Список устройств

| № | Требование | Приор. |
| --- | --- | --- |
| D-01 | У каждого аудиовыхода есть драйвер. Windows: `WASAPI`, `WASAPI Exclusive`, `ASIO` (только в сборке с `asio` и при наличии драйверов). Строка списка, поле строки «Выход», лог, `--list-devices` и `audio.output` — `[Драйвер]: Имя устройства` | M |
| D-02 | Порядок и нумерация: сначала выходы `WASAPI` в прежнем порядке (их индексы не меняются), затем те же выходы как `WASAPI Exclusive`, затем драйверы `ASIO`. Отметка умолчания `*` — только у устройства по умолчанию драйвера `WASAPI` | M |
| D-03 | `--audio-out` и `audio.output` ищут по полной строке `[Драйвер]: Имя`: по подстроке или индексу, первое совпадение. Значение из старого конфига без драйвера находит выход `WASAPI`, как раньше | M |
| D-04 | Все обращения к списку (`--list-devices`, раскрытие выпадающего списка, выбор строки, старт по конфигу) идут через одно перечисление — индексы везде совпадают | M |
| D-05 | Драйвер, который не удалось опросить (нет хоста ASIO, ошибка перечисления exclusive), даёт ноль строк и запись `warn` в лог; остальные строки списка остаются | M |
| D-06 | Поле устройства в строке «Выход» вмещает `[WASAPI Exclusive]: ` и имя до 28 знаков на минимальной сетке 96×36 (уточнено на шаге 1.2: больше не оставляет места частоте и размеру коллбэка); что не вмещается, обрезается с `…` в конце — и в поле, и в строках раскрытого списка, который по ширине равен полю. Список — контрол `gterm-widgets`, своей отрисовки нет (ADR 0018) | M |
| D-07 | Название драйвера — имя собственное, одинаковое в обеих локалях, в словарь не выносится | M |

### 4.2 WASAPI Exclusive

| № | Требование | Приор. |
| --- | --- | --- |
| E-01 | Поток открывается в монопольном режиме с пробуждением по событию. Частота — `--sample-rate` / `audio.sample_rate`, иначе частота микшера устройства. Формат — первый, который устройство принимает, в порядке: PCM 24 бита, PCM 16 бит | M |
| E-02 | Период — `audio.buffer_frames`, но не меньше минимального периода устройства; если устройство требует выровненный размер, берётся ближайший допустимый. Действующий размер показывается в строке «Выход» и пишется в лог вместе с форматом | M |
| E-03 | Аудио-поток — свой, с повышенным приоритетом; на каждое пробуждение один вызов `BlockRenderer::fill` и перевод f32 → формат устройства. В нём нет выделений памяти, блокировок и системных вызовов, кроме вызовов WASAPI (N-03) | M |
| E-04 | Измеритель, индикатор перегрузки и запись читают f32 до перевода в формат устройства — как сейчас | M |
| E-05 | Пропуск периода (устройство не дождалось данных) увеличивает счётчик `xrun` | S |
| E-06 | Отказ открытия выхода (устройство занято, монопольный режим запрещён в его свойствах, формат не принят) — при старте и при выборе из списка — запускает цепочку отката (ОР-3): то же устройство через `WASAPI` → устройство по умолчанию → первая строка списка, которая открылась. В строке «Выход» — сообщение, какой выход не открылся и почему; поле показывает выход, который звучит. Если не открылся ни один или список пуст — ошибка в строке «Выход», программа работает без звука. Значение `audio.output` откат не меняет: при следующем запуске выбранный выход пробуется снова | M |
| E-07 | Ошибка работающего потока (устройство отключено) — `warn` в лог, поток останавливается без паники; закрытие потока освобождает устройство для других программ | M |
| E-08 | Код, зависящий от Windows, собран в одном модуле `audio/`; на других ОС он не компилируется, строк `WASAPI Exclusive` нет | M |

### 4.3 ASIO

## 5. Контракты

```
sf2_player --list-devices
Audio outputs:
* [0] [WASAPI]: Наушники (2- QCY H3 Stereo)  44100 Hz, buffer 441..441 frames
  [1] [WASAPI]: Динамики (Realtek(R) Audio)  48000 Hz, buffer 480..480 frames
  [2] [WASAPI Exclusive]: Наушники (2- QCY H3 Stereo)  44100 Hz, buffer from 132 frames
  [3] [WASAPI Exclusive]: Динамики (Realtek(R) Audio)  48000 Hz, buffer from 144 frames
  [4] [ASIO]: Realtek ASIO  48000 Hz, buffer 1024..1024 frames      # только сборка с asio
```

```toml
[audio]
output = "[WASAPI Exclusive]: Динамики (Realtek(R) Audio)"
buffer_frames = 256
```

Строка «Выход»: `Аудио выход  [WASAPI Exclusive]: Динамики (Realtek(R) Audio)  ▾  48000 Hz / 256  OK` — после частоты число кадров одного коллбэка, без слова «кадров».

Ключи CLI и поля конфига не добавляются и не переименовываются.

## 7. Допущения (локальные, обратимые — BP-02.3)

- Д-1. На Linux строка списка — `[ALSA]: Имя устройства` (название хоста cpal): формат одинаков на всех ОС.
- Д-2. Версия пакета — 0.4.0.
- Д-3. Строка «Выход» для `WASAPI` начинает показывать действующий размер коллбэка (480), а не запрошенные 256, которые ни на что не влияют (§2).
- Д-4. Пока выход открыт в монопольном режиме, остальные программы через это устройство не звучат — свойство режима, описывается в README.
- Д-5. Перевод f32 → PCM 16 бит — округлением, без дизеринга, одной функцией (до решения ОР-4).

## 8. Решения владельца (AR-04), 23.11.2026

- **ОР-1. ASIO.** Принято: **перенести работу из `origin/develop` в `feature-ui` руками**, этапом после exclusive, с новым форматом строки; возможность сборки `asio` выключена по умолчанию, релизы без ASIO. Отклонены: отложить ASIO; слить `develop` в `feature-ui` (ветки разошлись на 46 коммитов, затронутые файлы с тех пор переписаны или удалены).
- **ОР-2. Как сделать exclusive.** Принято: **свой модуль на крейте `windows`** (MIT / Apache-2.0, уже в дереве зависимостей через cpal) — первый `unsafe` в проекте, вызовы COM собраны в одном файле. Отклонён: форк cpal с выбором режима.
- **ОР-3. Отказ открытия выхода.** Принято (ответ владельца: «Вариант 1, если тоже ошибка, то дефолт или первый пункт из списка. Если список пустой — показать ошибку и работа без звука»): **цепочка отката** — требование E-06. Отклонено: ошибка без звука сразу.
- **ОР-4. Дизеринг при переводе в 16 бит.** Не решено: владелец попросил объяснение (дано 23.11.2026). Варианты: (а) без дизеринга — рекомендация исполнителя; (б) TPDF. Открытое решение ведётся в плане; до ответа — Д-5.
