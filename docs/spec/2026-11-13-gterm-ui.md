## 1. Цель

Экран строится по тракту сигнала: **Источники MIDI → Обработчик → Выход**. Пользователь видит все три источника нот (текстовая клавиатура, MIDI-вход, MIDI-файл), выбранный обработчик (встроенный Synth или Sound Font) и оба выхода (аудиоустройство, файл записи), управляет ими мышью и клавиатурой. Приложение перестаёт зависеть от возможностей терминала: окно `gterm` даёт настоящее отпускание клавиш, физические коды клавиш и мышь.

Вне области: аудио-поток cpal и его lock-free обмен (N-03), движок rustysynth, кодировщики FLAC/Vorbis, формат существующих полей конфига, CLI (кроме §7), SF3 (F-18), монитор MIDI (F-08, остаётся в бэклоге), перемотка MIDI-файла, порт gterm на macOS.

## 4. Управление

### 4.1 Мышь (F-25)

Левая кнопка по кнопке `[…]` — действие; по клавише пианино — Note On при нажатии, Note Off при отпускании или уходе указателя с клавиши (при удержании и переходе на соседнюю клавишу — Note Off старой и Note On новой). Колесо и клик работают в списках диалогов (уже есть в `gterm-widgets`). Клик вне модального окна закрывает его как Esc.

### 4.2 Клавиатура

Принцип v1.0 сохраняется: буквенных команд нет, буквы и цифры заняты нотами; команды — F-клавиши, Ctrl/Alt-сочетания, небуквенные клавиши. Все действующие клавиши v1.1 сохраняют смысл (кроме ОР-3), добавляются:

| Клавиша | Действие | Статус |
| --- | --- | --- |
| Tab / Shift+Tab | фокус по кнопкам главного экрана (кольцо), Enter — нажать кнопку под фокусом | новое |
| F11 | диалог выбора MIDI-файла | новое |
| F12 | переключить обработчик Synth ⇄ Sound Font | новое |
| Space | старт / пауза MIDI-файла (Panic остаётся только на F9) | новое, ОР-3 A |
| Backspace | стоп MIDI-файла | новое, ОР-3 A |

Параметры Synth (форма, пресет ADSR, значения A/D/S/R) собственных горячих клавиш не получают — мышь или Tab + Enter. Справка F1 и таблицы README по-прежнему генерируются из одной таблицы привязок; `[keys]` в конфиге продолжает работать, новые команды получают имена.

Диалоги (модальный слой `gterm-widgets`): селекторы MIDI-входа, аудиовыхода, пресета — список с фильтром; эффекты — как в v1.1 §4.2. Enter — применить, Esc — отмена.

«Диалог ввода» — один вид окна для файла Sound Font, MIDI-файла и папки записи (Р-3): заголовок, строка ввода пути (курсор, ←→/Home/End, Backspace/Delete, вставка из буфера обмена), под ней список истории ранее введённых путей этого вида (до 10; ↑↓ или клик подставляют путь в строку), кнопки `[OK]` и `[Отмена]`. Enter равен `[OK]`, Esc — `[Отмена]`. Ошибка (нет файла, не тот формат, не каталог) показывается красным внутри диалога, диалог не закрывается. Tab в диалоге переводит фокус, как во всём интерфейсе; автодополнения по Tab нет (решение владельца 13.11.2026, П-3 плана: в `gterm-widgets` Tab всегда принадлежит кольцу фокуса) — путь дополняется выбором из списка подсказок (↓, Enter или клик), логика поиска вариантов берётся из `ui/path_input.rs`. Под строкой — список внутри самого диалога (решение владельца 13.11.2026, П-4 плана; библиотечного выпадающего компонента нет): по мере ввода он показывает подходящие каталоги и файлы, при пустой строке — историю; для папки записи предлагаются только каталоги, для файлов — каталоги и файлы с нужным расширением.

### 4.3 Текстовая клавиатура (меняет F-16)

- Ноты определяются **физическим кодом клавиши**, а не символом: раскладка работает при любом языке ввода.
- Note Off — всегда по отпусканию клавиши; автоповтор игнорируется по флагу события. Режим `gate`, поле `keyboard.gate_ms`, индикатор `kbd: release/gate` и подавление автоповтора X11 удаляются.
- При потере окном фокуса все ноты текстовой клавиатуры и мыши снимаются (отпускание вне окна не придёт).
- Диапазон — как в v1.0 (ОР-4 B): один ряд `Z X C V B N M , . /` и `S D G H J L ;`, C–E от базовой октавы. Пианино на экране показывает ровно этот диапазон (Р-4).
- Октава Ctrl+↓/↑, velocity Ctrl+←/→, Esc — как сейчас. Ноты не играют, пока открыт диалог или нажат Ctrl/Alt/Super.

## 5. Функциональные требования

Приоритеты: M — обязательно для v1.2, S — желательно.

### F-21. MIDI-файл как источник (M)

- Выбор файла `.mid`/`.midi` в диалоге (F11, кнопка `[MIDI-файл]`); Standard MIDI File формата 0 и 1; формат 2 и повреждённый файл — ошибка в строке «MIDI-файл». Чтение и запись SMF — собственный модуль `midi/smf.rs` (ОР-5 A).
- Транспорт: Старт (с начала или с места паузы), Пауза (звучащие ноты файла снимаются), Стоп (позиция в ноль, ноты сняты). По концу файла — автоматический Стоп. Перемотки нет.
- Темп и его смены (мета-событие Set Tempo) учитываются; позиция и длительность показываются в `mm:ss`.
- События файла идут в синтез тем же путём, что и MIDI-вход (F-07), с транспонированием и omni по общим правилам; текстовая клавиатура и MIDI-вход играют одновременно с файлом. События подаёт отдельный поток-секвенсор через собственное SPSC-кольцо (ОР-6 A); точность — как у живого MIDI-входа.
- Program Change из файла меняет пресеты каналов (как с устройства). После Стоп и конца файла: сброс контроллеров на всех каналах и повторное применение пресета F5 (v1.1 §4.1).
- Выбор другого файла во время воспроизведения — Стоп и замена. Путь файла и список недавних сохраняются в конфиг.

### F-22. Встроенный Synth (M; реализует F-17 v1.0)

- Второй движок за трейтом `SynthEngine` (сигнатура v1.0 §3 не меняется). Переключатель `[Synth] [Sound Font]` и F12 меняют движок на лету тем же механизмом, каким сейчас подменяется движок при смене банка; звучащие ноты при переключении снимаются. Выбор сохраняется в конфиг.
- Форма сигнала: синусоида, пила, треугольник; выбранная показана подсвеченной кнопкой, превью формы на экране нет (Р-8).
- Огибающая ADSR: Attack, Decay, Release — 0.001…2.000 с, шаг 0.005 с; Sustain — 0…100 %, шаг 5 %. Пресеты: Пианино (0.003 / 0.5 / 35 % / 0.35), Клавесин (0.002 / 0.28 / 20 % / 0.18), Орган (0.03 / 0.06 / 100 % / 0.09), Флейта (0.12 / 0.09 / 85 % / 0.22). Ручная правка значения помечает набор как «Своё».
- Объём движка (ОР-7 A): один тембр на все 16 каналов, включая канал 10 (ударные играют той же формой, не глушатся); полифония 64 голоса, при переполнении новая нота забирает самый старый голос; velocity → громкость; Pitch Bend ±2 полутона; CC 7, 64, 120/123; Program Change игнорируется.
- Эффекты: реверб и хорус работают на Synth. Алгоритмы — те же, что в rustysynth (Freeverb и модулируемая линия задержки; в rustysynth 1.3.8 они `pub(crate)`, поэтому код переносится в модуль sfplayer с уведомлением об авторстве и лицензии MIT). Вкл/выкл и уровни 0–127 — те же строка «Эффекты», диалог F6, клавиши Alt+R/Alt+C и поля конфига, что у Sound Font. Sound Font продолжает считать эффекты внутри rustysynth, его звучание не меняется.
- Движок соблюдает N-03: голоса и таблицы выделяются при создании, `render` и обработчики событий не аллоцируют. Изменение формы и ADSR применяется к новым нотам без пересоздания движка.
- Sound Font не обязателен для запуска: без банка приложение стартует на Synth, если так сохранено в конфиге; иначе — как сейчас (ошибка в строке «Файл Sound Font»).

### F-23. Запись MIDI и отмена записи (M; расширяет F-20)

- Третий формат записи — `MIDI`: в файл `.mid` (SMF формата 0) пишутся события, поданные в движок, от всех трёх источников, после транспонирования и omni, с метками времени по счётчику сэмплов аудио-потока. Аудио при этом формате не пишется; формат один на запись.
- Аудио-коллбэк только кладёт события в кольцо (N-03); файл пишет поток записи.
- `[Отмена]` (кнопка; горячей клавиши нет — ОР-3): запись останавливается, файл удаляется, в строке сообщений — «Запись отменена». Действует для всех трёх форматов.
- Индикатор записи показывает длительность, размер файла и имя; после остановки — «сохранено: <путь> · размер».
- Формат нельзя сменить во время записи (кнопки формата недоступны). Подтверждение выхода во время записи — как в v1.0.

### F-24. Экранное пианино и строки нот (M)

- Пианино 31×2 ячейки, по центру ширины окна: диапазон равен диапазону текстовой клавиатуры — от «до» базовой октавы до «ми» следующей (10 белых клавиш ряда Z…/, 7 чёрных ряда S…;), сдвигается вместе с базовой октавой; подсвечиваются (янтарным) ноты от **всех** источников, попадающие в диапазон. Ноты вне диапазона видны только названиями в строках нот.
- Строки «Клавиатура», «→ ноты» показывают названия звучащих нот соответствующего источника (`C4 E4 G4`, по возрастанию; не помещается — обрезка с `…`).
- Аудио-поток отдаёт UI карту звучащих нот по источникам через атомики (N-03), без очередей и аллокаций.
- Игра мышью — §4.1; velocity мыши равна velocity текстовой клавиатуры.

### F-25. Мышь и фокус (M)

§4.1 и кольцо фокуса §4.2. Любое действие экрана доступно и мышью, и с клавиатуры.

## 7. Конфиг и CLI

Новые поля (имена уточняются в плане, существующие поля не переименовываются):

```toml
[source]
midi_file = "/path/file.mid"        # последний выбранный MIDI-файл
recent_midi_files = []              # до 10

[synth]
engine = "sf2"                      # "sf2" | "builtin"

[synth.builtin]
wave = "sine"                       # "sine" | "saw" | "triangle"
adsr_preset = "piano"               # "piano" | "harpsichord" | "organ" | "flute" | "custom"
attack = 0.003
decay = 0.5
sustain = 0.35
release = 0.35

[record]
format = "flac"                     # добавляется значение "midi"

[ui]
font = ""                           # пусто = системный моноширинный
font_size = 14
```

Удаляются: `keyboard.gate_ms`, поле/ключ ASCII-глифов и CLI-флаг `--ascii`. Ключ `--log-level` теряет значение по умолчанию: лог пишется только при его указании (N-07). Добавляется CLI-ключ `--backend auto|gl|gles|soft` (передаётся в gterm; переменная `TERM_BACKEND` действует как в gterm). Незнакомые ключи старых конфигов не должны мешать запуску (поведение — как принято в `config.rs` сейчас; проверяется тестом).

## 8. Архитектура — что меняется

- UI-поток — главный поток процесса с циклом событий gterm (требование winit); обработчик `AppHandler` заменяет цикл `ui/app.rs`. Модель «UI читает атомики, шлёт команды в кольцо» сохраняется; `Session` и `session/control.rs` остаются точкой применения запросов.
- `src/ui/` переписывается на `gterm-widgets`: экран, диалоги, клавиши; логика без отрисовки (`keys.rs`, `text_keyboard.rs`, `path_input.rs`, `i18n.rs`) переносится с минимальными правками; `glyphs.rs` удаляется.
- Новые модули: `synth/builtin.rs` (F-22), `midi/smf.rs` — чтение и запись SMF, `midi/player.rs` — секвенсор (F-21), `record/midi.rs` (F-23), `ui/piano.rs` (F-24).
- `AudioShared` получает карту нот по источникам; `Command` — источник события; запись MIDI — кольцо «аудио → поток записи».
- Архитектурные решения оформляются ADR по мере принятия владельцем: переход на gterm и отказ от терминала/macOS (заменяет предпосылки ADR 0004, 0010), подача событий файла (ОР-6), собственный движок (ОР-7), чтение SMF (ОР-5), запись MIDI.
