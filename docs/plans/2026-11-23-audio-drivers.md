## 2. Решения

Решения владельца — ТЗ §8. Решения исполнителя при подготовке плана, в пределах отданного владельцем:

| № | Вопрос | Решение |
| --- | --- | --- |
| П-1 | Номер ADR | 0019 «Драйверы аудиовыхода: драйвер — часть выбора устройства; свой поток WASAPI Exclusive; ASIO — возможность сборки»; заменяет 0003. Пишется на шаге 1.1 и дополняется на шагах, где решение применяется |
| П-2 | Откуда список exclusive | Из того же перечисления cpal, что и `WASAPI`: имя — из описания устройства, конечная точка — по идентификатору `DeviceTrait::id` (`cpal-0.18.2/src/host/wasapi/device.rs:500`). Второго опроса имён нет, строки двух драйверов всегда парны |
| П-3 | Как коллбэк отдаёт не-f32 | Ядро `BlockRenderer::fill` остаётся на f32. Поток exclusive держит свой заранее выделенный буфер f32 на период и переводит его в формат устройства. Для ASIO (этап 3) решение переносится из `origin/develop` как есть: `fill`, обобщённый по типу сэмпла |
| П-4 | Порядок | Список и строка «Выход» раньше потока: после этапа 1 программа работает как прежде, но с драйвером в строке; exclusive и ASIO добавляют строки в готовый список |

## 3. Открытое решение (AR-04)

- **ОР-4. Дизеринг при переводе f32 → 16 бит** (ТЗ §8). Варианты: (а) без дизеринга; (б) TPDF. Шаг 2.1 делает перевод одной функцией по допущению Д-5 (без дизеринга); ответ владельца «(б)» меняет только её и её тесты.

## 4. Шаги

Каждый шаг: `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` зелёные → разделы в `docs/done/` и `docs/test/` (файл `2026-11-23-audio-drivers.md`) → `PROJECT_MAP.md` → один коммит. Изменение, видимое пользователю, — оба README в том же шаге. Базовый прогон гейтов — до первой правки (QG-08).
