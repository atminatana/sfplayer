## 4. Инварианты

- Аудио-коллбэк не затрагивается: `tests/no_alloc.rs` зелёный на каждом шаге.
- Справка F1 = таблицы README = таблица привязок (`readme_keys`).
- UI-тесты не открывают окно: только `ScreenBuffer` и маршрутизация `Ui`; всё, что требует окна, — в ручные проверки отчёта.
- Зависимость от `gterm` — только в `ui/window.rs`, рисовальщиках, модуле контролов главного экрана и модулях диалогов на контролах (ТЗ N-15).
- Деление файлов не смешивается с правками логики (ТЗ N-16).
- Старые конфиги открываются: имена команд `[keys]` не исчезают.
- В `gterm-git` — правила того репозитория; с `D:\Roman\Rust\gterm` работа не ведётся.

## 5. Риски

- **Выпадающий список на главном экране.** Дерево библиотеки там сейчас служит только для ввода; слой раскрытого списка нужно ещё и рисовать поверх экрана. Если встройка потребует правки библиотеки — владельцу до продолжения.
- **G-4 меняет ядро gterm** (события окна): затрагивает всех потребителей `PointerEvent`; golden и сравнение GL ↔ Software задеты быть не должны — проверяется гейтами gterm.
- **Размер `app.rs` и `window.rs`** после переезда модальных окон: проверяется на шаге 9.1.
- **Живые проверки.** Окно на этой машине снимается только при разблокированном сеансе; одна попытка на шаг, иначе пункт уходит владельцу.
- **Шаги 5.1 и 6.1 крупные:** если гейты не сходятся за один проход, шаг делится с пометкой в отчёте.
